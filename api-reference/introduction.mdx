Use the public API from server scripts and integration tools without a dashboard session.

## Public API areas

| Area | Use it for |
| --- | --- |
| [Authentication](/api-reference/authentication) | Choose a key and pass bearer authentication. |
| [Key identity](/api-reference/whoami) | Inspect permissions, path restrictions and server binding. |
| [FiveMesh CDN](/api-reference/cdn) | List, upload, delete and purge CDN objects; create scoped upload URLs. |
| [FiveMesh Logs](/api-reference/logs) | Ingest event batches and query stored events. |
| [FiveMesh Cache](/api-reference/cache) | Dashboard setup and operations; no public lifecycle endpoints. |
| [FiveMesh Voice](/api-reference/voice) | Dashboard setup and operations; no public lifecycle endpoints. |

## Base URLs

| API | Base URL |
| --- | --- |
| CDN, identity and Logs queries | `https://api.fivemesh.io/v1` |
| Logs ingestion | `https://logs.fivemesh.io` |

The SDK's `FIVEMESH_API_URL` includes `/v1`. Do not append another `/v1` when constructing requests from that value.

## Before you call the API

[Choose a key](/account/api-keys) with the required actions. The Server API Key covers uploads and Logs; a Developer API Key can provide narrower paths or additional actions.

```bash
curl "https://api.fivemesh.io/v1/whoami" \
  -H "Authorization: Bearer $FIVEMESH_API_KEY"
```

<Warning>
  Keep permanent keys on the server. Use scoped upload URLs for client-visible uploads.
</Warning>

CDN and query responses use `success` and `requestId`. Logs ingestion has its own `accepted` and `accepted_events` success format, with `request_id` in error bodies; see its endpoint reference.
